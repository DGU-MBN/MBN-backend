# K-PING 구현 계획 (2인 분담)

전제: MySQL 사용, PostGIS/pgvector 안 씀. `docs/구현_브리프.pdf`, `docs/api_명세서.pdf`, `docs/api_설명.pdf` 기반.

## 역할 분담 기준
- **A (유현)**: 외부 API 연동 + AI 파이프라인 전체. 실패 모드가 많고 판단이 필요한 영역.
- **B (정민)**: 도메인 스키마 + 표준 REST CRUD. 명세서만 보고 그대로 구현 가능한 영역.

## 0단계 (B, 반나절) — 공통 기반
- `domain/`: `Source, RawArticle, Event, EventLocation, EventEntity, Short, Artist, User, RenderJob` JPA 엔티티
- 스키마: `ddl-auto: update`로 시작 (Flyway는 필요해지면 추가)
- 위경도는 `double lat, double lng` + 복합 인덱스. PostGIS 없이 `/map/pins`의 bbox는
  `WHERE lat BETWEEN :minLat AND :maxLat AND lng BETWEEN :minLng AND :maxLng`
- 공통 `WebClient` Bean, 에러 응답 포맷(`code/message/detail`) `@ControllerAdvice`
- 상태값 enum 확정: `pin_type`, `confidence`, `source_type`, `license_status`, `interaction.type` (API 명세서 8장 표 그대로) — A/B 둘 다 참조하므로 여기서 못박기

0단계 끝나면 A/B 분리 진행. 공유 테이블 필드 변경 시 서로에게 알릴 것.

## A 트랙 — 파이프라인 + 외부 연동

1. **뉴스 수집 (A-1)**: `NaverNewsClient`(WebClient) + Jsoup 본문 크롤러, `content_hash` UNIQUE로 중복 방지
2. **클러스터링 (A-2)**: pgvector 없으니 Voyage 임베딩 생략. 같은 아티스트명+카테고리+72시간 이내로 1차 그룹핑 → 애매하면 Claude에게 "같은 사건이냐" 판단시키는 방식으로 대체
3. **팩트정리+현지화 (A-3, A-4)**: `ClaudeClient`, tool_use로 JSON 강제 → Jackson DTO. 언어별 호출 반드시 분리(번역 아님, 재작성)
4. **지오태깅 (A-5)**: `KakaoGeocodingClient` (국내), 필요시 Google Geocoding 폴백
5. **영상 렌더링 (A-6)**: TTS 연동 + `ProcessBuilder`로 FFmpeg 직접 호출, 소재 없을 때 `Graphics2D` 폴백 카드
6. **파이프라인 오케스트레이션**: `render_jobs`류 테이블 status 컬럼 + `@Scheduled` + `ThreadPoolTaskExecutor` (DB 폴링 방식, RabbitMQ 안 씀)
7. **운영 API**: `POST /admin/ingest`, `GET /admin/jobs/:job_id`, `GET /admin/events`, `PUT /admin/events/:event_id/review`

skipped: Voyage 임베딩, PostGIS, RabbitMQ — 규모 커지면 그때 추가.

## B 트랙 — 표준 REST

1. **사용자**: `POST /auth/device`(랜덤 토큰 발급 + DB 저장, JWT 안 씀), `GET/PUT /me/preferences`
2. **메타**: `GET /artists`, `GET /categories` (사전 데이터 시딩 포함)
3. **지도**: `GET /map/pins`(bbox 쿼리 + 줌레벨별 클러스터링은 zoom에 맞는 소수자리로 lat/lng 반올림 후 GROUP BY로 단순화), `GET /map/heatmap`(국가별 집계 배치 쿼리)
4. **피드/상세**: `GET /feed`, `GET /shorts/:id`, `GET /events/:id`, `GET /events/:id/variants`
5. **인터랙션**: `POST /shorts/:id/interactions` — 202 즉시 응답, 집계는 `@Scheduled` 배치로 처리 (A의 큐 방식과 동일 패턴)
6. **소스관리**: `GET/POST /admin/sources`, `PUT /admin/sources/:id` — 단순 CRUD

skipped: 세션 만료/리프레시 로직 — 필요해지면 추가.
